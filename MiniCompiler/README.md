# MiniCompiler

A small educational compiler front-end for a subset of the C language implemented using **Flex** (lexer) and **Yacc/Bison** (parser). The project performs lexical analysis, parsing, and symbol table construction (with scoped symbol tables) to demonstrate how a compiler handles tokens, grammar rules, and scope management.

---

## ✅ Features

- **Lexical analysis** via `flex` (`lex_analyzer.l`) with token recognition for:
  - Keywords: `if`, `else`, `for`, `while`, `do`, `break`, `continue`, `return`, `printf`, etc.
  - Types: `int`, `float`, `char`, `double`, `void`
  - Operators: arithmetic (`+`, `-`, `*`, `/`, `%`), relational (`<`, `>`, `==`, `!=`, etc.), logical (`&&`, `||`, `!`), increment/decrement (`++`, `--`)
  - Identifiers, integer literals, float literals, punctuation, and braces.

- **Syntax analysis** via `yacc`/`bison` (`syntax_analyzer.y`) supporting:
  - Declarations (variables, arrays)
  - Function definitions and parameter lists
  - Expressions (arithmetic, relational, logical)
  - Control flow (`if`, `if-else`, `while`, `for`)
  - `return` statements
  - `printf` (as `PRINTLN` token)

- **Symbol table management** with scoped hashing:
  - Multiple nested scopes tracked via `symbol_table.h`, `scope_table.h`, `symbol_info.h`
  - Function definitions, variables, and arrays stored with metadata
  - Scope enter/exit tracking and printing

- Outputs a log (`my_log.txt`) with:
  - Parser reductions (grammar rules used)
  - Symbol table contents per scope
  - Total number of lines processed

## 🧰 Prerequisites

You need the following tools installed and available in your PATH:

- **Flex** (lex)
- **Yacc/Bison** (`yacc` or `bison`)
- **GCC/G++** (C++ compiler)
- A Unix-like shell (Git Bash / WSL / Cygwin) or a compatible environment to run `script.sh`.

---

## 🏗️ Build & Run

### Option A: Use the provided build script (recommended)

From the project root:

```sh
./script.sh
```

This script will:

1. Run `yacc` to generate `y.tab.c` and `y.tab.h`
2. Compile the parser into `y.o`
3. Run `flex` to generate `lex.yy.c`
4. Compile the scanner into `l.o`
5. Link `y.o` and `l.o` to produce `a.exe`
6. Run `a.exe input1.c` (the default input file)

Output appears in:

- `a.exe` (executable)
- `my_log.txt` (parser/semantic logging)

### Option B: Manual build (if you want more control)

```sh
yacc -d -y --debug --verbose syntax_analyzer.y
g++ -w -c -o y.o y.tab.c
flex lex_analyzer.l
g++ -fpermissive -w -c -o l.o lex.yy.c
g++ y.o l.o -o MiniCompiler
./MiniCompiler input1.c
```

> ⚠️ On some systems, you may need to use `bison` instead of `yacc`.

## 📁 Project Structure

- `lex_analyzer.l` – Flex lexer definition
- `syntax_analyzer.y` – Yacc/Bison grammar and parser actions
- `symbol_info.h` – Symbol metadata model
- `symbol_table.h` – Scoped symbol table manager
- `scope_table.h` – Hash-based scope implementation
- `script.sh` – Build + run script
- `input1.c` – Default sample input
- `InputOutput/` – Additional input files and expected log outputs

## 🧪 Sample Inputs

Example source file: `input1.c`

```c
int func(int a, float b) {
    return a+b;
}

void main () {
    int a, b, c, i;
    int e, f[10], g[11];
    a = 1;
    b = 2;
    c = func(a, b);

    float d;
}
```

Logs generated by parsing this file are available under `InputOutput/log*.txt`.

## 📄 Notes

- This compiler accepts a small subset of C and is intended as a learning tool for compiler design.
- It focuses on lexing, parsing, and symbol table management, not on code generation or optimization.
